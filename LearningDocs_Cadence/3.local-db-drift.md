# Chunk 3: Local Database Layer with Drift

**Tags:** `#sqlite #drift #storage #offline-first #database`

## What this chunk does
Sets up Cadence's local relational database using Drift (an idiomatic, type-safe SQLite abstraction for Flutter and Dart). Configures database connection management across app lifecycles, defines the polymorphic shared `entries` table schema (with sync status tracking), and sets up code generation via `drift_dev` and `build_runner`.

## Why it's needed
Cadence is an **offline-first** personal operating system. The local database is the single source of truth for the app; the UI never waits on network requests to display or record user data. Establishing Drift gives us compile-time verified SQL queries, type-safe data classes, and reactive Dart `Stream`s that automatically emit updated data to Riverpod providers whenever a table changes.

## Key concepts

### 1. Drift (formerly Moor) vs Raw SQLite
Writing raw SQLite strings (`sqflite`) is error-prone: typoed column names, type mismatches (e.g. parsing `TEXT` to `DateTime`), and runtime crashes. Drift validates SQL schema definitions at compile time, generating immutable Dart classes for every table row, companion classes for inserts/updates, and reactive query streams.

### 2. The Shared `entries` Polymorphic Schema
To prevent table explosion for simple scalar entries (water glasses, sleep hours, mood ratings, habit ticks, quick journal notes), the design doc specifies a flexible polymorphic `entries` table:
- `id` (Text/UUID primary key)
- `userId` (Text/UUID for multi-user sync)
- `type` (Text: e.g. `'water'`, `'sleep'`, `'mood'`, `'habit'`, `'journal'`)
- `value` (Real/double: e.g. `8.0` glasses, `7.5` hours, `4.0` mood rating)
- `unit` (Nullable Text: `'glasses'`, `'hours'`)
- `note` (Nullable Text)
- `tags` (Text list encoded as JSON array or delimited string in SQLite)
- `metadata` (Nullable Text storing JSON payload for type-specific properties)
- `occurredAt` (DateTime: when the event happened in real life)
- `createdAt` / `updatedAt` (DateTime: timestamps for sync sorting)
- `isSynced` (Boolean: local flag indicating if the row has been pushed to Supabase)

### 3. Reactive Query Streams
Drift queries can be watched as `Stream<List<Entry>>`. When an insert, update, or delete occurs on the `entries` table, Drift notifies all active stream subscribers automatically. Riverpod `StreamProvider` consumes these streams, instantly re-rendering UI widgets without manual state dispatching.

### 4. Native SQLite on Android and Linux
Drift uses `sqlite3_flutter_libs` to bundle the latest stable C SQLite engine directly inside the app, avoiding quirks and missing features across different Android vendor OS versions.

## How it works

1. **Table Definition (`lib/core/database/tables/entries_table.dart`):** Defines the `Entries` table DSL extending `Table`.
2. **Database Engine (`lib/core/database/app_database.dart`):** Annotates `@DriftDatabase(tables: [Entries])`. Opens the SQLite file in the application's document directory via `NativeDatabase.createInBackground` (running SQLite disk I/O on a separate background isolate to prevent UI thread frame drops).
3. **Riverpod Wiring (`lib/core/database/database_provider.dart`):** Declares a global `appDatabaseProvider` that exposes a singleton database instance.
4. **Code Generation:** Running `dart run build_runner build` parses the schema and generates `app_database.g.dart` containing data classes (`Entry`), companions (`EntriesCompanion`), and query builders.

## Gotchas / trade-offs

- **JSON & Array Types in SQLite:** SQLite does not natively support `text[]` (Postgres array) or `jsonb`. In Drift, array tags and metadata objects are stored as JSON-encoded text strings, with Drift type converters converting them transparently to/from Dart `List<String>` and `Map<String, dynamic>`.
- **Primary Keys & UUID Generation:** We generate UUID v4 strings locally on the device prior to insertion rather than relying on auto-incrementing integer IDs. This ensures rows created offline never collide with IDs generated on other devices during Supabase sync.
- **Isolate Threading:** Performing heavy database reads or writes on the main UI thread causes jank. Drift's background native executor offloads queries to an isolate transparently.

In `test/widget_test.dart`, disposing `ProviderScope` right before test completion left this timer pending in `fakeAsync`, triggering an assertion failure.
